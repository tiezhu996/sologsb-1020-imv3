# 档案元数据核对台

`sologsb-1020` 是一个用于口述史与手稿档案元数据比对的本地优先前端工作台，使用 Qwik、TypeScript 和 Qwik UI 构建。

## 功能

- 导入 A / B 两组记录，支持 JSON 数组、制表符和竖线分隔文本。
- 按标题、日期、人物、地点和编号加权匹配，显示综合分数与判断依据。
- 键盘密集复核：J/K 移动、Enter 合并、C/R 确认或忽略，支持批量操作。
- 合并时逐字段并排展示 A / B 来源，每个冲突字段可单独保留或拼接。
- 保存原始记录、字段来源选择、合并结果和忽略动作，形成完整审计轨迹。
- 支持撤销重做、离线 localStorage 保存和 JSON 核对包导出。
- 大量记录采用分批窗口渲染，匹配计算限制每条记录的候选数，避免一次挂载全部行。

## 离线修订合并（馆内主档 ↔ 现场批次）

- 现场批次带回的修订包记录主档基线号 `baselineRevision` 与本地改稿 `edits`，格式为 JSON：`{"batchId":"FIELD-251005","baselineRevision":3,"edits":[{"identifier":"OH-...","changes":{...},"baseValues":{...}}]}`。
- 导入时按记录编号做三方合并（基线值 / 馆内主档 / 现场批次）：只有单边改过的字段直接采纳并写清来源；两边都改过的字段并列保留、标出基线原值，进入冲突裁决队列。
- 存在待裁决冲突的记录会被锁定，确认与合并（含批量操作）一律挡住，人工选定事实来源后才放行。
- 馆内主档与现场批次互不覆盖：现场新增编号只追加新记录，冲突字段在裁决前不写入主档。
- 大批量导入按每批 20 条分批处理；暂停、断网或写入失败时，失败包、处理进度和回滚点留在工作区，可续作或一键回滚到导入前状态。
- 记录索引、匹配队列、冲突说明、审计轨迹和导出核对包都标注修订来源（馆内主档 / 现场批次号 / 合并生成及对应修订号）。
- 「载入示例修订包」会模拟批次离场后馆内的两处改稿，再导入现场修订包，可一次演示自动采纳、保留主档、双边冲突和现场新增四种情形。

## 技术栈

- Qwik 1.20
- TypeScript 5.9
- Qwik UI Headless `@qwik-ui/headless`
- Vite 7

## 开发

```bash
npm install
npm run dev
```

开发服务使用 Vite 默认端口，不在源码中硬编码宿主端口。

## 生产构建

```bash
npm run build
npm run preview
```

静态产物输出到 `dist/`。

## Docker

```bash
docker build -t sologsb-1020 .
docker run --rm -p 10020:80 sologsb-1020
```

nginx 在容器内监听 `80`，宿主端口 `10020` 由根端口表或运行命令映射。

## 数据说明

记录和审计轨迹保存在当前浏览器。导入新记录后自动重新计算候选匹配，但不会自动确认或覆盖任何字段。
